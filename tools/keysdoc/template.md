# Keys: the two tables, the source names, the key names

Generated by `go run ./tools/keysdoc` from the tables the agent uses
(`internal/merc`, `internal/keys`, `profile.StandInDefault`) and the prose in
`tools/keysdoc/template.md`; change those, not this file.

The keyboard has two matrix tables. In **table 1**, the power-on table (`table: legend` in
a Mod), every key sends what is printed on it: a pad key is the same usage as the main key
with that legend, and the numpad sends the firmware's shortcuts with Num Lock off and keypad
keys with it on. In **table 2** (`table: standin`) the pad and most of the numpad send
usages of their own, so the agent can tell them from the main keys; Num Lock changes nothing
at the keyboard.

**A stand-in Mod with no bindings behaves like table 1.** For every key the Mod leaves
unbound, the agent sends the legend-table result itself (the "Unbound" column below): pad
keys their legends, the numpad its shortcuts with Num Lock off and keypad keys with it on.
The one departure is Restore and Maximize with Num Lock off: in table 1 the firmware drives
the window menu by position, which misses on a Windows 11 menu, so the agent sends Win+Down
and Win+Up for them instead. A Mod that should be table 1 except for a few pad keys is
`table: standin` with only those keys bound:

```yaml
table: standin
keys:
  pad.w:                 # everything else as in table 1
    chord:
      - left-ctrl
      - w
```

"Table 2 sends" is also the name `zengine -debug` logs for the key. A source name is written
exactly as in the first column (`pad.prt-scr` and `backlight.color`, for example).
On Windows the consumer usages of table 2 (nine pad keys and numpad *) reach the agent from
the collection itself, since Windows' HID service passes only one of them at a time and
repeats few; the agent repeats a held one at the keyboard delay and rate.
The Scroll Lock and Pause keys carry Restore and Maximize as their Num Lock-off meaning:
`scroll-lock` binds the key in both states, `restore` only with Num Lock off and ahead of
it, and neither exists in a legend Mod's Num Lock-off state, where the firmware's macro runs.

## Main-block keys

The main block is an ordinary keyboard in both tables: a key's source name is its key name
below, and it cannot be told from the pad key with the same legend in table 1.
